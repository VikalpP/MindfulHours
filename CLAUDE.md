# MindfulHours: maintainer notes

macOS menu-bar app (Swift 6, SwiftPM, no Xcode project) that records frontmost app, window title and URL every few seconds and asks an LLM (Apple's on-device model by default), once per active minute, what the person is doing inside the app. Logic lives in `MindfulHoursCore` (tested); macOS integration and SwiftUI live in `MindfulHours`. See README.md for features and CONTRIBUTING.md for setup.

```sh
swift build && swift test
scripts/build-app.sh --install          # build, sign, install to /Applications, launch
scripts/take-screenshots.sh             # refresh docs/screenshots (Mac must be unlocked)
scripts/release.sh X.Y.Z               # signed + notarized release into dist/X.Y.Z/, prints publish commands
scripts/release.sh X.Y.Z --publish     # same, then tag + gh release (on main, in sync with origin)
```

## Decisions — don't reverse without asking the owner

- **Screenshots are withheld per page, not per app.** A protected tab (password manager, private window…) blocks screenshots of that page only; other pages of the same app still get theirs. A security review suggested app-level blocking; the owner rejected it. The post-capture re-check (same page, no protection seen during capture) covers the real race.
- **Title/URL are hidden only when they are themselves sensitive** (excluded app, sensitive URL rule, sensitive title word). Other protections (password field, capture-blocked window, private window, on-screen secrets, unverifiable browser) skip the screenshot but keep and send the metadata.
- **Fail closed** when a privacy signal can't be determined (browser URL or private mode unreadable, Safari menu in a non-English UI): withhold the screenshot.
- **One AI call per active minute**, describing the app with the most total time that minute (not the single longest page; terminal titles change constantly). Secondary apps are shown from activity checks as Timeline chips and lanes. The owner chose this over per-app AI descriptions to limit provider usage and cost.
- **Tracking starts at launch; only screenshots wait** for the on-device text scanner to warm up (~30 s once after reboot), so no time is lost.
- **Releases are built on the founder's Mac, not in CI** (founder chose "Option A", Nov 2026; there is no release workflow and no signing secrets on GitHub). `scripts/release.sh` matches what the old release workflow did (Xcode ≥ 27 check, `swift test`, universal `build-app.sh`, weak-link check) and adds notarization of both the app and the DMG: Developer ID signing with hardened runtime + entitlements + secure timestamp, notarize + staple the app, then a signed, notarized, stapled DMG, a zip of the stapled app and `SHA256SUMS.txt` in `dist/<version>/`. Notarization uses the Keychain profile `mindfulhours-notary` (App Store Connect API key); the Developer ID Application identity is in the login keychain. Guards: clean tree, new tag (local, origin, GitHub), identity and profile present, `RELEASE_NOTES.md` (untracked, in `.git/info/exclude`) present. Build number is `git rev-list --count HEAD`. Without `--publish` it prints the tag + `gh release create` commands for the exact built commit; `--publish` refuses to run off main or when main differs from origin/main. v0.2.0 is the first Developer ID build, so users re-grant Accessibility, Screen Recording and Keychain access once.
- **Apple Intelligence is the default provider (v0.2.0, founder-approved).** Picker order: Apple Intelligence → ChatGPT (labelled preview) → Ollama/LM Studio (RAM note) → Claude/OpenAI/Gemini keys → OpenRouter → Custom; `AIProvider` case order is the picker order. Default rule (`ProviderSelection`, tested): a persisted `aiProvider` (written by the picker) wins; otherwise Apple Intelligence, except on Macs that can never run it (macOS < 26, Intel, a build without FoundationModels), which get ChatGPT. Nothing else pins a provider: a saved key or ChatGPT sign-in doesn't change the default until the user picks it.
- **Apple Intelligence falls back only to a backup the user picks** (Settings, default "Record app and title only"). The preset is sold as on-device and private, so it never silently sends minutes to whatever cloud provider happens to have a key. Throttling (`rateLimited`, `concurrentRequests`, `timeout`) backs off 1→2→4→8→15 min; a guardrail/refusal or unavailable model sends just that minute to the backup (or metadata) without backing off; nothing retries in a loop (`OnDeviceFirstRouter`, tested with mock models). Only `SystemLanguageModel` is used, never `PrivateCloudComputeLanguageModel` (it's in the macOS 27 SDK; using it would break the privacy claim).
- **Users pick a provider preset, not a URL**: Apple Intelligence, Sign in with ChatGPT, OpenRouter sign-in, Claude/OpenAI/Gemini API keys, Ollama/LM Studio, or Custom (base URL + key) for pro users. All credentials live in one Keychain item so an updated ad-hoc-signed build prompts once; if that item exists but can't be read (access denied), nothing is saved, so it is never overwritten.
- **Claude is API-key only.** Anthropic's terms forbid other apps from using Claude subscription sign-ins, so no subscription-proxy setups either; only ChatGPT offers plan sign-in for open-source local apps (Responses API, `store: false`, `stream: true`, no `temperature` or `max_output_tokens`). Custom is documented neutrally, for OpenAI-compatible endpoints the user runs or trusts.

## Lessons from testing (not visible in the code)

- **Minute calls must send `reasoning_effort: "none"`** (Claude preset: `thinking: {type: disabled}`, since Anthropic's endpoint ignores `reasoning_effort`). Without it, Haiku 5.5 spent the whole `max_tokens` budget on hidden reasoning and returned empty content (`finish_reason: length`).
- **Prompt history lists only app + task label, never earlier summaries.** With summaries, the model described an earlier Chrome minute for a Terminal-only minute 4 of 4 times. The current minute goes last, in a block marked "describe only this".
- **Task labels must be judged from the current minute.** "Reuse recent labels" made one wrong label propagate (a YouTube lecture tagged as the coding task). After any prompt change, re-test both cases against a live provider (Apple Intelligence and one cloud model).
- **Apple Intelligence API facts (macOS 27 SDK)**: text works on macOS 26; `Attachment(cgImage)`, `capabilities.contains(.vision)` and `LanguageModelError` are macOS 27 and need the Xcode 27 SDK, so that code sits behind `#if compiler(>=6.4)`. Only Xcode 27 is verified (CI enforces it); `contextSize` and `tokenCount` come from the 26.4 SDK, so Xcode 26.0–26.3 likely won't compile. macOS 26 throws `LanguageModelSession.GenerationError` (deprecated in 27); both are mapped in `AppleIntelligence.classify`. `contextSize` returns a hard-coded 4096 before macOS 27 (8192 on the owner's Mac), and `tokenCount(for:)` needs 26.4, so budgets use `contextSize` with a 3-chars-per-token fallback. Vision is confirmed with one real image request per macOS build and cached in defaults (`appleIntelligenceVisionSupport`). The `@Generable` minute struct replaces the JSON reply format (`Prompts.onDeviceMinuteSystem`).
- **Apple Intelligence live checks** (`MINDFULHOURS_LIVE_AI=1 swift test --filter LiveAppleIntelligence`, skipped in CI): on macOS 27.2 (build 26B131) the vision probe passed and a minute read "Fix token refresh in session.ts" from the image alone; both prompt regressions above passed; a 300-minute day takes ~40 s in parts; free text dropped the Work log/Focus layout, so the final call uses guided generation (`OnDeviceDaySummary`), and it still under-reports the middle of very long days. Labels are weaker than cloud models (task "Router.swift" for a title-only minute). About 1.3–3 s per minute call.
- **Real background run (Nov 2026, battery power)**: an isolated copy recorded minutes with `apple-on-device` descriptions and was never throttled, but it made only 3 fresh calls (an unchanged window reuses the description), so throttling is not ruled out. The copy has no Screen Recording grant, so the real run is text-only; vision was verified by the live test instead.
- **FoundationModels is weak-linked automatically** (`LC_LOAD_WEAK_DYLIB`, checked in CI and by `release.sh` for both slices), which keeps the app launching on macOS 14/15. If that check ever fails, add `-weak_framework FoundationModels` via `linkerSettings`.
- **CI needs the `xcode-27` runner** (`macos-26` defaults to Xcode 26.6 without the macOS 27 SDK); `ci.yml` and `scripts/release.sh` both fail early on an older Xcode so a release can't silently drop screenshot support.
- **Registered defaults are process-wide**, even across `UserDefaults(suiteName:)` instances, so tests must not call `register(defaults:)`; use a scratch suite, which holds only what's persisted.
- **The menu popup must keep a constant height.** MenuBarExtra doesn't redraw its rounded corners and shadow when it resizes while open.
- **Window snapshots (`--snapshot-*`)**: launch with `open`, not the binary, or macOS checks the terminal's permissions; use `open -g` for the popup so it shows the real front app; keep 1 pt of the window on screen and re-pin it after each resize, or ScreenCaptureKit fails with -3811; a locked screen can't be captured.
- **Without Screen Recording permission, every window reports "no sharing"**, so the capture-blocked check only runs once permission is granted.
- **Isolated test launches**: run a copy with a different bundle id (separates defaults and Keychain) and `CFFIXED_USER_HOME=<scratch>` (`HOME` alone does not move Application Support, so the real DB would be used). Run the binary directly; `--snapshot-*` then fails without Screen Recording for the copy, but still runs launch. `defaults` still land in the real `~/Library/Preferences/<id>.plist`; delete it afterwards.
- **The Developer ID key needs a one-time keychain approval.** Its first `codesign` from a terminal or agent blocks on a "codesign wants to access key" dialog (click Always Allow); a non-interactive run just hangs, so sign a scratch file once before `release.sh`.
- **Relaunching right after `pkill`** fails with LaunchServices error -600; `build-app.sh` waits for the old process to exit.

## State outside the repo
